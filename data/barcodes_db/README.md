# Кэш штрихкодов

Локальная база **не импортируется вручную**. Она наполняется автоматически при сканировании.

## Как это работает

1. **Первый скан** штрихкода → запрос в **Open Food Facts** (онлайн)
2. При успешном ответе продукт сохраняется в таблицу `barcode_cache` (SQLite на native, IndexedDB на web)
3. **Повторный скан** того же штрихкода → данные из **локального кэша** (offline)

## Порядок поиска

| Шаг | Источник | Условие |
|-----|----------|---------|
| 1 | Локальный кэш | Штрихкод уже сканировали ранее |
| 2 | Каталог API | `EXPO_PUBLIC_PRODUCT_DB=true`, backend запущен |
| 3 | Open Food Facts | Есть интернет, продукта нет в кэше и каталоге |
| 4 | Анализ как текст | Не найден нигде |

## Что хранится

- Штрихкод (EAN/GTIN)
- Название продукта
- Состав (ingredients)
- Источник (`openfoodfacts`)
- Даты кэширования

Кэш привязан к устройству, не к профилю пользователя.
