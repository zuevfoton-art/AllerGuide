# Промт для генерации тест-кейсов AllerGuide

Этот документ — **готовый промт**, который можно передать LLM (или использовать как бриф для QA-инженера) для генерации тест-кейсов по функциональности приложения **AllerGuide**.

Промт самодостаточен: он содержит контекст продукта, формат вывода, перечень функциональных областей и обязательные правила покрытия. Скопируйте раздел [«Промт»](#промт) целиком. При необходимости ограничить охват — задайте параметры в блоке «Область тестирования».

> Источник истины по функциональности — `docs/functional-requirements.md` (идентификаторы `FR-*`). Промт ссылается на эти ID, чтобы тест-кейсы были трассируемы.

---

## Как пользоваться

1. Откройте раздел [«Промт»](#промт) и скопируйте его целиком в чат с LLM.
2. (Опционально) В блоке «Область тестирования» оставьте только нужные модули — например, `Сканер` и `Дневник` — чтобы сузить генерацию.
3. (Опционально) Приложите к запросу актуальный `docs/functional-requirements.md`, чтобы модель опиралась на точные требования.
4. Получите тест-кейсы в заданном формате и при необходимости попросите модель догенерировать негативные/граничные сценарии по конкретной области.

---

## Промт

````text
РОЛЬ
Ты — старший QA-инженер мобильных приложений. Твоя задача — спроектировать
полный, структурированный набор тест-кейсов для приложения AllerGuide.

КОНТЕКСТ ПРОДУКТА
AllerGuide — мобильное приложение (Expo / React Native) для управления
аллергией, для пользователей и родителей детей-аллергиков. Работает на iOS,
Android и Web.
Ключевые свойства, которые ОБЯЗАТЕЛЬНО влияют на тест-кейсы:
- Язык UI по умолчанию — русский; поддерживаются 6 языков
  (ru, en, es, fr, de, it). Выбор языка сохраняется локально.
- Offline-first: основные функции работают без сети. Сеть нужна только для
  Open-Meteo (индекс самочувствия, карта), Open Food Facts (штрихкод
  продукта) и синхронизации с сервером.
- Данные хранятся локально: SQLite на native, localStorage на web.
- Различия платформ ОБЯЗАТЕЛЬНО учитывать:
  * Web — ограниченный режим: нет сканирования штрихкода камерой,
    нет push-напоминаний, вместо SQLite используется localStorage.
  * iOS/Android — полный функционал (камера, геолокация, push, SQLite).
- Везде, где есть медицинский контент, должен присутствовать disclaimer:
  приложение не ставит диагноз и не заменяет врача.
- Все рекомендации/индексы носят информационный характер.

ФУНКЦИОНАЛЬНЫЕ ОБЛАСТИ (покрыть каждую; в скобках — связанные требования)
1. Аутентификация и аккаунт (FR-AUTH-01…07)
   - Регистрация и вход по телефону или email + пароль.
   - Валидация: email; телефон 10–15 цифр; пароль ≥ 6 символов;
     подтверждение пароля при регистрации.
   - Редирект неавторизованного пользователя на экран входа.
   - Выход из аккаунта; удаление аккаунта и всех данных.
2. Онбординг и первый запуск (FR-ONB-01…06)
   - Intro из 5 слайдов, возможность пропуска, сохранение факта просмотра.
   - Выбор сценария: «для себя» / «для ребёнка» / «для себя и ребёнка».
   - Двухшаговый wizard для сценария «для себя и ребёнка»
     (сначала «Я», потом «Ребёнок»).
   - Автоматический bootstrap-маршрут по наличию профилей и
     завершённости онбординга.
3. Профили (FR-PROF-01…11)
   - Поля: имя, год рождения, тип (я / ребёнок), список аллергенов.
   - Каталог аллергенов из 10 типов состояний, выбор подкатегорий.
   - Обязательное согласие родителя при создании детского профиля.
   - Создание нескольких профилей, редактирование, удаление с каскадным
     удалением записей дневника и связанных данных.
   - Переключение активного профиля; повторное нажатие на активный
     профиль открывает редактирование.
   - Экстренные контакты профиля (имя, телефон, тип).
   - Условные модули дневника: «Пикфлоуметрия» только при бронхиальной
     астме; «АСИТ» при поллинозе/рините/бытовой/животной аллергии.
4. Главный экран / индекс самочувствия (FR-HOME-01…08)
   - Индекс 0–100 на основе Open-Meteo (пыльца, EAQI, PM2.5),
     релевантности пыльцы профилю и недавних записей дневника.
   - Факторы и персональные рекомендации; обновление при смене профиля.
   - Быстрые строки дневника и быстрые ссылки; кнопка SOS.
5. Дневник наблюдений (FR-DIARY-01…07)
   - Типы записей: Симптомы, Лекарство, Питание, Триггер, Кожа,
     Пикфлоуметрия, АСИТ, Визит к врачу, Заметка.
   - Полный wizard (все разделы подряд) и быстрое добавление по разделу.
   - Создание, редактирование (с сохранением структурированных ответов),
     удаление с подтверждением.
   - История по активному профилю, сортировка новые-сверху, summary записи.
6. Отчёт для врача (FR-DIARY-08…12)
   - Выбор периода 7 / 14 / 30 дней и блоков отчёта.
   - Генерация PDF, упоминание АДАИР; disclaimer.
7. Умный сканер (FR-SCAN-01…10)
   - Режимы: Продукт, Меню, Лекарство, Косметика.
   - Продукт: сканирование штрихкода камерой (EAN-13/8, UPC, Code128)
     + запрос к Open Food Facts; распознавание ручного ввода штрихкода
     (8–14 цифр).
   - Меню: фото / ручной ввод состава.
   - Анализ по ключевым словам аллергенов профиля + перекрёстные реакции.
   - Вердикт с уровнем риска (низкий/средний/высокий), список совпадений,
     перекрёстных совпадений и источника данных.
   - История последних 5 сканирований активного профиля.
8. Маркет (FR-MARKET-01…05)
   - Каталог, персональная подборка по аллергенам, скрытие конфликтующих
     товаров, поиск, карточка товара.
9. Карта мест (FR-MAP-01…10)
   - Слои: Рестораны, Пыление, АДАИР.
   - Интерактивная карта на native, заглушка на web, геолокация
     по разрешению, фильтрация по аллергенам.
10. Экспертный раздел (FR-EXP-01…04)
    - Категории материалов, просмотр статей, disclaimer.
11. SOS (FR-SOS-01…08)
    - Данные профиля (имя, возраст, аллергены), мед. заметки и план
      действий, экстренные контакты со звонком в одно нажатие,
      настраиваемый экстренный номер (по умолчанию 103).
12. Настройки (FR-SET-01…07)
    - Экстренный номер, тема (светлая/тёмная/системная), напоминание
      дневника (push, только mobile), экспорт/импорт резервной копии
      (JSON), синхронизация с сервером, ссылки на правовые документы.
13. Данные и синхронизация (FR-DATA-01…05)
    - Локальное хранение, web-fallback, привязка профилей к userId,
      формат резервной копии (JSON v1 с timestamp), round-trip
      экспорт→импорт без потери данных.
14. Локализация и UX (FR-UX-01…06)
    - 6 языков, сохранение выбора, темы, нижняя навигация, переключатель
      профиля на основных экранах, обязательные disclaimer'ы.

ТИПЫ СЦЕНАРИЕВ, КОТОРЫЕ НУЖНО ПОКРЫТЬ
- Позитивные (happy path) для каждой функции.
- Негативные: пустые/некорректные поля, неверный формат email/телефона,
  слишком короткий пароль, несовпадение паролей, отсутствие выбранного
  аллергена, отсутствие согласия для детского профиля.
- Граничные: год рождения < 1900 или > текущего; штрихкод ровно 8 и 14
  цифр; индекс самочувствия на границах 0 и 100; период отчёта на границах;
  пустой дневник; профиль без аллергенов.
- Состояния без данных (empty state): нет профилей, нет записей дневника,
  нет истории сканов, нет экстренных контактов.
- Различия web vs native: камера, push, хранилище (см. контекст).
- Сетевые сбои и offline: поведение индекса самочувствия, сканера по
  штрихкоду и синхронизации при отсутствии сети / ошибке API.
- Разрешения ОС: камера, геолокация, уведомления (выдано / отклонено).
- Мультипрофильность: корректная изоляция данных между профилями,
  обновление экранов при переключении профиля.
- Локализация: переключение языка обновляет UI и сохраняется;
  отсутствие «сырых» ключей перевода.
- Доступность: контраст уровней риска, крупные touch-targets на SOS.
- Безопасность данных: каскадное удаление, удаление аккаунта стирает
  все связанные данные.

ФОРМАТ ВЫВОДА
Сгруппируй тест-кейсы по функциональным областям (заголовок раздела).
Внутри каждой области выведи тест-кейсы в виде таблицы Markdown со столбцами:

| ID | Заголовок | Приоритет | Платформа | Предусловия | Шаги | Ожидаемый результат | Связь с FR |

Правила оформления:
- ID: формат TC-<КОД ОБЛАСТИ>-<номер>, напр. TC-AUTH-001, TC-SCAN-007.
- Приоритет: P0 (критичный) / P1 (высокий) / P2 (средний) / P3 (низкий).
  P0 — пути, без которых продукт неработоспособен или небезопасен
  (вход, создание профиля, SOS-звонок, вердикт сканера, каскадное удаление).
- Платформа: iOS / Android / Web / Все.
- Шаги: пронумерованный список лаконичных действий (1; 2; 3 …).
- Ожидаемый результат: конкретный, проверяемый, по одному на тест-кейс.
- Связь с FR: один или несколько идентификаторов FR-*.
- Язык тест-кейсов — русский.

ТРЕБОВАНИЯ К ПОКРЫТИЮ
- Каждое требование FR-* из перечисленных областей должно быть покрыто
  минимум одним тест-кейсом.
- Для каждой ключевой функции — минимум один позитивный и один
  негативный/граничный тест-кейс.
- Не выдумывай функциональность, которой нет в контексте. Раздел 18 ТЗ
  (push о пыльце, напоминания о визите, OCR упаковок, marketplace с
  оплатой, телемедицина, PIN/биометрия, восстановление пароля) —
  НЕ реализован: тест-кейсы по нему НЕ создавай (можно отметить как
  «вне области» при необходимости).
- В конце добавь короткую таблицу трассируемости: FR-ID → список TC-ID.

ОБЛАСТЬ ТЕСТИРОВАНИЯ (заполни при необходимости; по умолчанию — все)
- Включить области: <все | перечисли номера/названия областей>
- Платформы: <Все | iOS | Android | Web>
- Глубина: <smoke | regression | полный>

НАЧНИ С короткого плана покрытия (1–2 предложения на область), затем выдай
тест-кейсы по разделам, в конце — таблицу трассируемости.
````

## Подсказки по уточнению (follow-up)

После первичной генерации можно догенерировать узкие срезы, например:

- «Сформируй только P0 smoke-набор для регрессии перед релизом.»
- «Расширь негативные и граничные тест-кейсы для области Сканер (FR-SCAN-*).»
- «Добавь тест-кейсы различий Web vs native для всех областей.»
- «Преобразуй тест-кейсы области Дневник в формат Gherkin (Given/When/Then).»
- «Сгенерируй чек-лист локализации для 6 языков по экранам из матрицы экранов.»
