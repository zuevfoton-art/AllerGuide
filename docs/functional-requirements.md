## 1. Назначение продукта

AllerGuide — мобильное приложение-помощник для людей с аллергией и их родителей. Продукт помогает:

- вести персональный дневник наблюдений;
- проверять продукты и состав на совпадение с профилем аллергий;
- ориентироваться в среде (пыльца, качество воздуха, места, клиники);
- быстро показывать экстренную медицинскую информацию;
- формировать отчёты для визита к врачу;
- получать экспертный справочный контент (АДАИР).

**Важно:** приложение не ставит диагноз, не назначает лечение и не заменяет консультацию врача. Все рекомендации носят информационный характер.

## 2. Платформы и роли

### 2.1. Платформы

| Платформа | Требование |
|-----------|------------|
| iOS / Android | Полный функционал (камера, геолокация, push, SQLite) |
| Web (Expo) | Ограниченный режим: без камеры штрихкодов, без push; **IndexedDB** (не localStorage) — см. [`architecture.md`](./architecture.md) |

### 2.2. Роли пользователей

| Роль | Описание |
|------|----------|
| **Пользователь (взрослый)** | Ведёт собственный профиль, дневник, SOS |
| **Родитель / законный представитель** | Ведёт профиль ребёнка; при создании детского профиля подтверждает законное согласие |
| **Гость (неавторизованный)** | Доступ только к экранам входа и регистрации |

## 3. Общие требования к UX

- **FR-UX-01.** Интерфейс поддерживает 6 языков: русский (по умолчанию), английский, испанский, французский, немецкий, итальянский.
- **FR-UX-02.** Выбор языка доступен на экране входа и в разделе «Мои профили»; выбор сохраняется локально.
- **FR-UX-03.** Светлая тема по умолчанию; поддержка тёмной темы и системного режима.
- **FR-UX-04.** Нижняя навигация (6 вкладок): Главная, Дневник, Сканер, Маркет, Карта, SOS.
- **FR-UX-05.** Переключение активного профиля доступно на основных экранах (главная, дневник, сканер, маркет, карта, SOS).
- **FR-UX-06.** На всех экранах с медицинским контентом отображается disclaimer о рекомендательном характере информации.

## 4. Аутентификация и аккаунт

### 4.1. Регистрация и вход

- **FR-AUTH-01.** Регистрация и вход по **телефону** или **email** с паролем.
- **FR-AUTH-02.** Валидация email и телефона (10–15 цифр для телефона).
- **FR-AUTH-03.** Пароль — минимум 6 символов; при регистрации — подтверждение пароля.
- **FR-AUTH-04.** После успешного входа пользователь попадает в сценарий bootstrap (intro → onboarding → профиль → главная).
- **FR-AUTH-05.** Неавторизованный пользователь перенаправляется на экран входа.

### 4.2. Управление аккаунтом

- **FR-AUTH-06.** Удаление аккаунта и всех связанных данных (профили, дневник, история сканов) — с экрана «Мои профили».
- **FR-AUTH-07.** Выход из аккаунта.

> **Планируется (не в текущей реализации):** PIN-код, биометрия, восстановление пароля, OAuth.

## 5. Онбординг и первый запуск

  - только для ребёнка;
  - для себя и ребёнка.

### 5.3. Создание профилей

- **FR-ONB-05.** Для сценария «для себя и ребёнка» — двухшаговый wizard: сначала профиль «Я», затем профиль «Ребёнок».
- **FR-ONB-06.** Bootstrap-маршрут определяется автоматически по наличию профилей и завершённости onboarding.

## 6. Профили пользователей

### 6.1. Структура профиля

- **FR-PROF-01.** Профиль содержит: имя, год рождения, тип (я / ребёнок), список аллергенов.
- **FR-PROF-02.** Аллергены и **типы аллергических состояний** выбираются из каталога с группировкой по **11 типам** (ТЗ v13 + крапивница). Типы состояния (`profileConditions`) задают gating модулей дневника и рекомендуемые шкалы; аллергены (`profiles.allergies`) — каталог для сканера и cross-reactions:

  1. Пищевая аллергия  
  2. Поллиноз  
  3. Бронхиальная астма  
  4. Аллергический ринит  
  5. Атопический дерматит  
  6. **Крапивница / ангиоотёк** (`urticaria`) — рекомендует шкалу UAS7  
  7. Бытовая аллергия  
  8. Аллергия на животных  
  9. Лекарственная аллергия  
  10. Инсектная аллергия  
  11. Другие виды аллергии  

  Для типов с подкатегориями (еда, поллиноз, быт, животные, насекомые, лекарства) option id сопоставляется с canonical allergen id через `condition-allergen-map.ts` (Phase 0/4).
- **FR-PROF-03.** Для типов с подкатегориями доступен выбор конкретных аллергенов / option id в wizard состояний.
- **FR-PROF-04.** При создании профиля ребёнка требуется явное согласие родителя/законного представителя.

### 6.2. Управление профилями

- **FR-PROF-05.** Создание нескольких профилей в одном аккаунте.
- **FR-PROF-06.** Редактирование профиля (имя, год рождения, аллергены).
- **FR-PROF-07.** Удаление профиля с каскадным удалением записей дневника и связанных данных.
- **FR-PROF-08.** Переключение активного профиля; повторное нажатие на активный профиль открывает редактирование.
- **FR-PROF-09.** При создании профиля можно добавить экстренные контакты (имя, телефон, тип: родственник / доверенное лицо / врач).

### 6.3. Условная доступность модулей дневника

- **FR-PROF-10.** Раздел «Пикфлоуметрия» доступен, если пользователь **явно** отметил тип состояния **бронхиальная астма** (эвристика по аллергенам не включает модуль).
- **FR-PROF-11.** Раздел «АСИТ» доступен, если **явно** отмечены поллиноз, ринит, бытовая или животная аллергия.
- **FR-PROF-12.** Единый слой `ProfileCapabilities` (`packages/core/src/profile-capabilities.ts`) управляет видимостью разделов дневника, быстрых действий на главной, блоков PDF-отчёта, напоминаний и дефолтного режима сканера. **Карта, маркетплейс и все режимы сканера всегда доступны** независимо от типов состояний. Шкала **UAS7** рекомендуется в дневнике при явном типе **крапивница / ангиоотёк** (`urticaria`) или эвристике по аллергенам профиля (`diary-profile.ts`).
- **FR-PROF-13.** При выборе аллергена без соответствующего типа состояния показывается мягкая подсказка «Добавить тип» (без автоматического включения модулей). Разделы «Питание», «Лекарство», «Укус насекомого» и карточки специализированных модулей доступны по **явным** типам состояния и данным профиля (см. `food-drug-allergy.ts`, `insect-allergy.ts`) — **без скрытия** сканера, карты и маркетплейса.
- **FR-PROF-14.** Для каждого явно выбранного типа состояния пользователь может указать **хронологию**: период дебюта, год (опционально), текущий статус, источник подтверждения; для пищевой аллергии — время симптомов после еды (EAACI allergy-focused history); для ринита — флаг глазных симптомов (ARIA ocular). Хранение: `app_settings` → `conditionHistory:{profileId}`.
- **FR-PROF-15.** При **≥2 типах** состояний пользователь может указать **связи коморbidности** (что появилось раньше / одновременно). Хранение: `conditionHistory` v:2 → `comorbidityLinks[]`.
- **FR-PROF-16.** На основе типов, хронологии, аллергенов и SOS (анафилаксия) приложение **выводит клинические фенотипы** (`resolveClinicalPhenotypes`) — только рекомендации и подсказки на главной и в дневнике; **не влияет** на gating сканера, карты, маркетплейса или модулей дневника.
- **FR-PROF-17.** PDF-отчёт для врача включает блок **«Хронология и фенотипы профиля»** (`conditionPhenotypes`) при наличии данных.

## 7. Главный экран (Dashboard)

- **FR-HOME-01.** Отображение заголовка «Сегодня» и имени активного профиля.
- **FR-HOME-02.** **Сводка самочувствия (wellness index)** — интегральный индекс 0–100 на основе:
  - данных Open-Meteo (пыльца, EAQI, PM2.5);
  - релевантности пыльцы профилю пользователя;
  - недавних записей дневника (симптомы, триггеры за 48 ч).
- **FR-HOME-03.** Визуализация факторов: пыльца, качество воздуха, записи дневника (progress bars).
- **FR-HOME-04.** Персональные рекомендации на основе индекса и профиля.
- **FR-HOME-05.** Блок «Дневник» — быстрые строки: Симптомы, Питание, Лекарство с переходом в дневник.
- **FR-HOME-06.** Быстрые ссылки: Сканер, Карта, Маркет, Эксперт.
- **FR-HOME-07.** Кнопка перехода на экран SOS.
- **FR-HOME-08.** Disclaimer: индекс не заменяет консультацию аллерголога.

> **Планируется:** push-оповещения при высоком уровне пыльцы по профилю.

## 8. Дневник наблюдений

### 8.1. Типы записей

- **FR-DIARY-01.** Поддерживаемые разделы дневника (baseline §7.3 — **done**):

| Раздел | Содержание |
|--------|------------|
| Симптомы | Каталог (SNOMED/ICD), свободный текст, выраженность **0–3**, зоны, время начала |
| Лекарство | Препарат, дозировка, время приёма, эффект/побочные реакции |
| Питание | Блюдо/продукты, **состав по компонентам**, аллергены, реакция после еды |
| Триггер | Источник, контекст, детали (+ автоподстановки) |
| Кожа | Зона, внешний вид, зуд, **фото проявлений**, заметки |
| Пикфлоуметрия | Время (утро/вечер), ПСВ (л/мин), лучшее значение, комментарий |
| АСИТ | Препарат, схема, дата/время, субъективная реакция |
| Укус насекомого | Тип, тяжесть, действия (при insect-focus профиле) |
| Визит к врачу | Тип врача, дата/время, комментарий |
| Заметка | Свободная текстовая запись |
| Шкала | Клинические шкалы (ARIA / ACT / SCORAD / UAS7 и др.) как тип `Шкала` |

Baseline также включает **индекс самочувствия 0–100** (пыльца/AQI + дневник) на главной и **PDF-отчёт врачу** за период — см. FR-HOME / FR-DIARY-08…12.

### 8.2. Создание и редактирование

- **FR-DIARY-02.** Пошаговый wizard для полной записи (все разделы подряд).
- **FR-DIARY-03.** Быстрое добавление по одному разделу (горизонтальные chips).
- **FR-DIARY-04.** Редактирование существующей записи с сохранением структурированных ответов.
- **FR-DIARY-05.** Удаление записи с подтверждением.
- **FR-DIARY-06.** История записей активного профиля, отсортированная по дате (новые сверху).
- **FR-DIARY-07.** Форматирование даты и краткое summary записи для списка.

### 8.3. Отчёт для врача

- **FR-DIARY-08.** Переход на экран формирования PDF-отчёта из дневника.
- **FR-DIARY-09.** Выбор периода: 7 / 14 / 30 дней.
- **FR-DIARY-10.** Выбор блоков отчёта: симптомы, лекарства, питание, триггеры, пикфлоуметрия, АСИТ, кожа, заметки/визиты.
- **FR-DIARY-11.** PDF содержит логотип/упоминание АДАИР и научного руководителя (проф. Смолкин Ю.С.).
- **FR-DIARY-12.** Disclaimer: отчёт не является медицинской документацией.

### 8.4. Расширения дневника (§7.3 — фазы A–C)

- **FR-DIARY-photo** *(Phase A — done).* В секции «Кожа» можно прикрепить до 5 фото проявлений (камера / галерея). Файлы хранятся локально; миниатюры видны в ленте; фото включаются в PDF-отчёт. Удаление записи удаляет вложения.
- **FR-DIARY-dish-breakdown** *(Phase B — done).* После ввода блюда в «Питание» мастер предлагает чеклист типичных ингредиентов (локальный каталог) с возможным обогащением из Open Food Facts / product catalog. Отмеченные компоненты сверяются с аллергиями профиля (прямые и перекрёстные), конфликты подсвечиваются; поле аллергенов предзаполняется.
- **FR-DIARY-voice** *(Phase C — done).* На текстовых шагах wizard доступен голосовой ввод (OS / on-device STT через `expo-speech-recognition`; Web Speech API в Chromium). Распознанный текст вставляется в текущее поле; для «Симптомы» лёгкий парсер может заполнить severity / onset / зону / код каталога, если поля пустые. Отказ в permission или ошибка STT не ломают wizard (text-fallback).

> **Планируется:** облачное хранение фото, расширение каталога блюд («свой компонент»), push-напоминания о визите к врачу.

## 9. Умный сканер аллергенов

### 9.1. Режимы сканирования

- **FR-SCAN-01.** Четыре режима: **Продукт**, **Меню**, **Лекарство**, **Косметика**.
- **FR-SCAN-02.** Режим «Продукт»: сканирование штрихкода камерой (EAN-13, EAN-8, UPC, Code128) с запросом к Open Food Facts.
- **FR-SCAN-03.** Режим «Меню»: фото меню / ручной ввод состава (демо-анализ типичного меню).
- **FR-SCAN-04.** Ручной ввод состава / штрихкода для всех режимов.

### 9.2. Анализ результата

- **FR-SCAN-05.** Проверка текста состава по ключевым словам аллергенов активного профиля.
- **FR-SCAN-06.** Учёт **перекрёстных реакций** из справочника аллергенов.
- **FR-SCAN-07.** Вердикт с уровнем риска: низкий / средний / высокий.
- **FR-SCAN-08.** Отображение совпадений, перекрёстных совпадений, источника данных (Open Food Facts, штрихкод, ручной ввод).
- **FR-SCAN-09.** История последних сканирований активного профиля (до 5 записей).
- **FR-SCAN-10.** Disclaimer: результат предварительный, не исключает индивидуальной реакции.

> **Планируется:** полноценный OCR меню, распознавание состава с упаковки лекарств и косметики.

## 11. Карта мест

- **FR-MAP-01.** Три переключаемых слоя:
  1. **Рестораны** — заведения с оценкой безопасности для аллергиков;
  2. **Пыление** — сезонный календарь пыления по месяцам;

### 11.2. Слой «Рестораны»

- **FR-MAP-02.** Интерактивная карта с маркерами (native); заглушка на web.
- **FR-MAP-03.** Геолокация пользователя (с разрешением).
- **FR-MAP-04.** Список рекомендованных мест с уровнем: высокий / средний / низкий.
- **FR-MAP-05.** Фильтрация мест по аллергенам профиля.

### 11.3. Слой «Пыление»

- **FR-MAP-06.** Отображение пиков пыления для текущего месяца (регион Москва, ориентир АДАИР / Open-Meteo).
- **FR-MAP-07.** Карточки аллергенов с месяцем пика и регионом.

### 11.4. Слой «АДАИР»

- **FR-MAP-08.** Список верифицированных клиник АДАИР (адрес, телефон, запись).
- **FR-MAP-09.** Список врачей: ФИО, степень, специализация, привязка к клинике.
- **FR-MAP-10.** Отметка НККЦ и главного медицинского эксперта АллерГайд.

## 13. SOS — экстренная информация

- **FR-SOS-01.** Экран экстренной информации для активного профиля.
- **FR-SOS-02.** Отображение: имя, возраст (из года рождения), список аллергенов.
- **FR-SOS-03.** Медицинские заметки и **план действий** при аллергической реакции (редактируемые).
- **FR-SOS-04.** Список экстренных контактов с возможностью звонка одним нажатием.
- **FR-SOS-05.** Кнопка вызова экстренного номера (настраиваемый, по умолчанию **103**).
- **FR-SOS-06.** Редактирование SOS-данных на отдельном экране.
- **FR-SOS-07.** Подсказка: показать экран медработнику при анафилаксии.
- **FR-SOS-08.** Disclaimer: информация внесена пользователем, не является медицинским назначением.

## 14. Настройки

## 15. Данные и синхронизация

- **FR-DATA-01.** Локальное хранение на native: SQLite (профили, дневник, настройки, история сканов, контакты).
- **FR-DATA-02.** Web-fallback: **IndexedDB** с in-memory cache и async write-through (legacy localStorage мигрируется один раз).
- **FR-DATA-03.** Привязка профилей к userId после авторизации; миграция legacy-данных.
- **FR-DATA-04.** Формат резервной копии: JSON v1 с timestamp экспорта.
- **FR-DATA-05.** Backend API (Express + PostgreSQL): маршруты auth и sync.

## 20. Критерии приёмки (общие)

1. Пользователь может пройти полный путь: регистрация → intro → сценарий → профиль → главная.
2. Для каждого типа записи дневника создаётся, редактируется и удаляется запись с корректным summary.
3. Сканер возвращает вердикт с учётом аллергенов профиля и перекрёстных реакций.
4. Wellness index на главной обновляется при смене профиля и наличии сети.
5. PDF-отчёт формируется за выбранный период с выбранными блоками.
6. SOS-экран показывает актуальные данные профиля и инициирует звонок.
7. Резервная копия экспортируется и импортируется без потери данных.
8. Все медицинские экраны содержат обязательный disclaimer.
