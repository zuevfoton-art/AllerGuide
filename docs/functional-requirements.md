## 1. Назначение продукта

AllerGuide — мобильное приложение-помощник для людей с аллергией и их родителей. Продукт помогает:

- вести персональный дневник наблюдений;
- проверять продукты и состав на совпадение с профилем аллергий;
- ориентироваться в среде (пыльца, качество воздуха, места, клиники);
- быстро показывать экстренную медицинскую информацию;
- формировать отчёты для визита к врачу;
- получать экспертный справочный контент (АДАИР).

**Важно:** приложение не ставит диагноз, не назначает лечение и не заменяет консультацию врача. Все рекомендации носят информационный характер.

## 2. Платформы и роли

### 2.1. Платформы

| Платформа | Требование |
|-----------|------------|
| iOS / Android | Полный функционал (камера, геолокация, push, SQLite) |
| Web (Expo) | Ограниченный режим: без камеры штрихкодов, без push; **IndexedDB** (не localStorage) — см. [`architecture.md`](./architecture.md) |

### 2.2. Роли пользователей

| Роль | Описание |
|------|----------|
| **Пользователь (взрослый)** | Ведёт собственный профиль, дневник, SOS |
| **Родитель / законный представитель** | Ведёт профиль ребёнка; при создании детского профиля подтверждает законное согласие |
| **Гость (неавторизованный)** | Доступ только к экранам входа и регистрации |

## 3. Общие требования к UX

- **FR-UX-01.** Интерфейс поддерживает 6 языков: русский (по умолчанию), английский, испанский, французский, немецкий, итальянский.
- **FR-UX-02.** Выбор языка доступен на экране входа и в разделе «Мои профили»; выбор сохраняется локально.
- **FR-UX-03.** Светлая тема по умолчанию; поддержка тёмной темы и системного режима.
- **FR-UX-04.** Нижняя навигация (6 вкладок): Главная, Дневник, Сканер, Маркет, Карта, SOS.
- **FR-UX-05.** Переключение активного профиля доступно на основных экранах (главная, дневник, сканер, маркет, карта, SOS).
- **FR-UX-06.** На всех экранах с медицинским контентом отображается disclaimer о рекомендательном характере информации.

## 4. Аутентификация и аккаунт

### 4.1. Регистрация и вход

- **FR-AUTH-01.** Регистрация и вход по **телефону** или **email** с паролем.
- **FR-AUTH-02.** Валидация email и телефона (10–15 цифр для телефона).
- **FR-AUTH-03.** Пароль — минимум 6 символов; при регистрации — подтверждение пароля.
- **FR-AUTH-04.** После успешного входа пользователь попадает в сценарий bootstrap (intro → onboarding → профиль → главная).
- **FR-AUTH-04a.** При входе / cold start авторизованного пользователя профили подтягиваются (backend при наличии сети, иначе локальная БД), сразу выбирается активный профиль и его данные доступны экранам. Если профилей несколько (родитель и ребёнок) — активным становится профиль родителя (`type = self`).
- **FR-AUTH-05.** Неавторизованный пользователь перенаправляется на экран входа.

### 4.2. Управление аккаунтом

- **FR-AUTH-06.** Удаление аккаунта и всех связанных данных (профили, дневник, история сканов) — с экрана «Мои профили».
- **FR-AUTH-07.** Выход из аккаунта.

> **Планируется (не в текущей реализации):** PIN-код, биометрия, восстановление пароля, OAuth.

## 5. Онбординг и первый запуск

### 5.1. Intro-слайды

- **FR-ONB-01.** При первом входе показывается intro из 5 слайдов: дневник, сканер, маркет, карта, эксперт.
- **FR-ONB-02.** Intro можно пропустить; факт просмотра сохраняется локально.

### 5.2. Выбор сценария

- **FR-ONB-03.** Пользователь выбирает сценарий использования:
  - только для себя;
  - только для ребёнка;
  - для себя и ребёнка.
- **FR-ONB-04.** Сценарий сохраняется и определяет маршрут создания профилей.

### 5.3. Создание профилей

- **FR-ONB-05.** Для сценария «для себя и ребёнка» — двухшаговый wizard: сначала профиль «Я», затем профиль «Ребёнок».
- **FR-ONB-06.** Bootstrap-маршрут определяется автоматически по наличию профилей и завершённости onboarding.

## 6. Профили пользователей

### 6.1. Структура профиля

- **FR-PROF-01.** Профиль содержит: имя, год рождения, тип (я / ребёнок), список аллергенов.
- **FR-PROF-02.** Аллергены и **типы аллергических состояний** выбираются из каталога с группировкой по **11 типам** (ТЗ v13 + крапивница). Типы состояния (`profileConditions`) задают gating модулей дневника и рекомендуемые шкалы; аллергены (`profiles.allergies`) — каталог для сканера и cross-reactions:

  1. Пищевая аллергия  
  2. Поллиноз  
  3. Бронхиальная астма  
  4. Аллергический ринит  
  5. Атопический дерматит  
  6. **Крапивница / ангиоотёк** (`urticaria`) — рекомендует шкалу UAS7  
  7. Бытовая аллергия  
  8. Аллергия на животных  
  9. Лекарственная аллергия  
  10. Инсектная аллергия  
  11. Другие виды аллергии  

  Канонические allergen id выбираются на шаге аллергенов; карта `condition-allergen-map.ts` остаётся справочником соответствий тип↔аллергены (Phase 0/4).
- **FR-PROF-03.** Конкретные аллергены выбираются на шаге аллергенов (не на шаге типов). Для типа **«Другие виды аллергии»** на шаге типов доступно **текстовое поле** названия (`app_settings` → `otherConditionLabel:{profileId}`).
- **FR-PROF-04.** При создании профиля ребёнка требуется явное согласие родителя/законного представителя.

### 6.2. Управление профилями

- **FR-PROF-05.** Создание нескольких профилей в одном аккаунте.
- **FR-PROF-06.** Редактирование профиля (имя, год рождения, аллергены).
- **FR-PROF-07.** Удаление профиля с каскадным удалением записей дневника и связанных данных.
- **FR-PROF-08.** Переключение активного профиля; повторное нажатие на активный профиль открывает редактирование. Предпочтительный активный при входе — `self` (см. FR-AUTH-04a).
- **FR-PROF-09.** При создании профиля можно добавить экстренные контакты (имя, телефон, тип: родственник / доверенное лицо / врач).

### 6.3. Условная доступность модулей дневника

- **FR-PROF-10.** Раздел «Пикфлоуметрия» (ПСВ) доступен, если пользователь **явно** отметил тип состояния **бронхиальная астма** (эвристика по аллергенам не включает модуль). Пищевая и прочие типы **не** открывают ПСВ.
- **FR-PROF-11.** Раздел «АСИТ» доступен, если пользователь **явно** отметил тип **поллиноз** (эвристика по аллергенам не включает модуль). Пищевая аллергия, ринит, бытовая и животная **без** поллиноза модуль АСИТ не открывают.
- **FR-PROF-12.** Единый слой `ProfileCapabilities` (`packages/core/src/profile-capabilities.ts`) управляет видимостью разделов дневника, быстрых действий на главной, блоков PDF-отчёта, напоминаний и дефолтного режима сканера. **Карта, маркетплейс и все режимы сканера всегда доступны** независимо от типов состояний. Шкала **UAS7** рекомендуется в дневнике при явном типе **крапивница / ангиоотёк** (`urticaria`) или эвристике по аллергенам профиля (`diary-profile.ts`).
- **FR-PROF-13.** При выборе аллергена без соответствующего типа состояния показывается мягкая подсказка «Добавить тип» (без автоматического включения модулей). Разделы «Питание», «Лекарство», «Укус насекомого» и карточки специализированных модулей доступны по **явным** типам состояния и данным профиля (см. `food-drug-allergy.ts`, `insect-allergy.ts`) — **без скрытия** сканера, карты и маркетплейса.
- **FR-PROF-14.** Для каждого явно выбранного типа состояния пользователь может указать **хронологию**: период дебюта, **возраст дебюта** (год рассчитывается из года рождения), текущий статус, источник подтверждения (чипы: Самонаблюдение / Подтверждено анализами / Подтверждено врачом); для пищевой аллергии — время симптомов после еды (EAACI allergy-focused history); для ринита — флаг глазных симптомов (ARIA ocular). Хранение: `app_settings` → `conditionHistory:{profileId}`.
- **FR-PROF-15.** При **≥2 типах** состояний пользователь может указать **связи коморbidности** (что появилось раньше / одновременно). Хранение: `conditionHistory` v:2 → `comorbidityLinks[]`.
- **FR-PROF-16.** На основе типов, хронологии, аллергенов и SOS (анафилаксия) приложение **выводит клинические фенотипы** (`resolveClinicalPhenotypes`) со **справочными кодами МКБ-10** — только рекомендации и подсказки; **не является диагнозом** и **не влияет** на gating сканера, карты, маркетплейса или модулей дневника.
- **FR-PROF-17.** PDF-отчёт для врача включает блок **«Хронология и фенотипы профиля»** (`conditionPhenotypes`) при наличии данных.
- **FR-PROF-18.** Wizard `/profile-setup`: после аллергенов — шаг **перекрёстных реакций** (`crossReactions`, ids хранятся отдельно от primary `allergies` в `crossReactionAllergies`); затем шаг **подтверждения аллергенов** (`allergenConfirmations`); auto-skip если совпадений/аллергенов нет. Порядок: types → allergens → cross → **confirmations** → symptoms → history → comorbidity → phenotype → contacts.
- **FR-PROF-19.** На шаге типов пользователь выбирает только типы состояний (+ свободный текст для `other`); конкретные аллергены — на шаге `allergens`. Связанные пищевые позиции из перекрёстов **не** добавляют тип «пищевая аллергия» автоматически и не мержатся в основной список аллергенов.
- **FR-PROF-20.** Шаг **симптоматики профиля** (`symptomBaseline`): зоны, usual severity, до 8 кодов из `SYMPTOM_CATALOG`; опционален (Skip). Хранение: `app_settings` → `symptomBaseline:{profileId}`. Не является записью дневника.
- **FR-PROF-21.** Телефон на регистрации и в экстренных контактах — единый `PhoneInput` (код страны по умолчанию +7, маска национального номера).

## 7. Главный экран (Dashboard)

- **FR-HOME-01.** Единый `ScreenBrandHeader`: центрированный знак A-Claro и слоган «Aclearo — когда важна ясность» (`brand.slogan`, 6 локалей). Справа — иконка профиля → `/profile` и кнопка SOS. Переключатель профилей на главной не показывается.
- **FR-HOME-02.** **Сводка самочувствия (wellness index)** — интегральный индекс 0–100 на основе:
  - данных Open-Meteo (пыльца, EAQI, PM2.5);
  - релевантности пыльцы профилю пользователя;
  - недавних записей дневника (симптомы, триггеры за 48 ч).
- **FR-HOME-03.** Визуализация факторов на слое 2 (по запросу «Подробности»): пыльца, качество воздуха, записи дневника (исходные числа / progress bars).
- **FR-HOME-04.** Персональные рекомендации на основе индекса и профиля.
- **FR-HOME-05.** Блок «Дневник» — быстрые строки: Симптомы, Питание, Лекарство с переходом в дневник.
- **FR-HOME-06.** Быстрые ссылки: Сканер, Карта, Маркет, Эксперт.
- **FR-HOME-07.** Кнопка перехода на экран SOS.
- **FR-HOME-08.** Disclaimer (две строки): индекс самочувствия информационный и не заменяет консультацию врача; при ухудшении — обратиться к специалисту.
- **FR-HOME-09.** Сводка самочувствия двухслойная: слой 1 — статус, X/100, словесные категории и главный фактор; слой 2 — исходные числа по запросу.
- **FR-HOME-10.** Пользовательские рекомендации на главной не называют ACT/ARIA/GINA; клиническая логика остаётся внутри системы. Напоминание о терапии — краткая строка.

> **Планируется:** push-оповещения при высоком уровне пыльцы по профилю.

## 8. Дневник наблюдений

### 8.1. Типы записей

- **FR-DIARY-01.** Поддерживаемые разделы дневника (baseline §7.3 — **done**):

| Раздел | Содержание |
|--------|------------|
| Симптомы | Каталог (SNOMED/ICD), свободный текст, выраженность **0–3**, зоны, время начала |
| Лекарство | Препарат, дозировка, время приёма, эффект/побочные реакции |
| Питание | Блюдо/продукты, **состав по компонентам**, аллергены, реакция после еды |
| Триггер | Источник, контекст, детали (+ автоподстановки) |
| Кожа | Зона, внешний вид, зуд, **фото проявлений**, заметки |
| Пикфлоуметрия | Время (утро/вечер), ПСВ (л/мин), лучшее значение, комментарий |
| АСИТ | Препарат, схема, дата/время, субъективная реакция |
| Укус насекомого | Тип, тяжесть, действия (при insect-focus профиле) |
| Визит к врачу | Тип врача, дата/время, комментарий |
| Заметка | Свободная текстовая запись |
| Шкала | Клинические шкалы (ARIA / ACT / SCORAD / UAS7 и др.) как тип `Шкала`; ввод на `/clinical-scales`, не в ленте дневника |

Baseline также включает **индекс самочувствия 0–100** (пыльца/AQI + дневник) на главной и **PDF-отчёт врачу** за период — см. FR-HOME / FR-DIARY-08…12.

### 8.2. Создание и редактирование

- **FR-DIARY-02.** Пошаговый wizard для полной записи: адаптивный маршрут по профилю без PEF/АСИТ/визита/терапии и без auto-шагов (пыльца/скан/лекарства дня, зоны симптомов, эффект лекарства).
- **FR-DIARY-03.** На экране дневника сверху: «Новая запись», «Короткая запись», «Что добавить»; ниже — история; ещё ниже — «Дополнительные модули наблюдения». Визит к врачу и клинические оценки — отдельные действия.
- **FR-DIARY-04.** Редактирование существующей записи с сохранением структурированных ответов.
- **FR-DIARY-05.** Удаление записи с подтверждением.
- **FR-DIARY-06.** История записей активного профиля, отсортированная по дате (новые сверху). Записи типа «Шкала» скрыты из ленты, но сохраняются в БД и PDF.
- **FR-DIARY-07.** Форматирование даты и краткое summary записи для списка.

### 8.3. Отчёт для врача

- **FR-DIARY-08.** Переход на экран формирования PDF-отчёта из дневника.
- **FR-DIARY-09.** Выбор периода: 7 / 14 / 30 дней **или произвольный диапазон дат** (включая многолетнюю историю).
- **FR-DIARY-10.** Выбор блоков отчёта по профилю и фактическим данным периода: симптомы, лекарства, питание, триггеры, контекст, пикфлоуметрия, астма, АСИТ, терапия по назначению, пищевая/инсектная аллергия, кожа, шкалы, заметки. Нерелевантные блоки скрываются.
- **FR-DIARY-11.** PDF использует брендинг A-Claro; упоминание проф. Смолкина **не** включается в шапку отчёта (экспертный контент АДАИР — отдельно, FR-EXP-01).
- **FR-DIARY-12.** Disclaimer: отчёт не является медицинской документацией.
- **FR-DIARY-13.** Модуль **АСИТ**: аллерген из каталога, препарат (текст + фото/PDF назначения с OCR и экраном верификации), дата начала через date picker, активация курса только после финального подтверждения схемы и напоминаний. Запись приёма не дублирует сохранённые поля курса.
- **FR-DIARY-14.** Клинические шкалы вынесены на `/clinical-scales`. Пикфлоуметрия остаётся модулем наблюдения при бронхиальной астме.
- **FR-DIARY-15.** Модуль **терапии по назначению врача** (аналог АСИТ): OCR назначения → верификация → напоминания → отметки приёма и история в дневнике/PDF. На итоговом обзоре при включённом ежедневном напоминании можно задать **несколько времён** приёма в сутки (`reminderTimes[]`, до 6; legacy `reminderHour`/`reminderMinute` = первое время).
- **FR-DIARY-16.** Быстрая отметка питания **без** шагов «возможные аллергены» и «перекрёстные реакции»; тип реакции «Реакция во рту и горле» (OAS — в подсказке).

### 8.4. Расширения дневника (§7.3 — фазы A–C)

- **FR-DIARY-photo** *(Phase A — done).* В секции «Кожа» можно прикрепить до 5 фото проявлений (камера / галерея). Файлы хранятся локально; миниатюры видны в ленте; фото включаются в PDF-отчёт. Удаление записи удаляет вложения.
- **FR-DIARY-dish-breakdown** *(Phase B — done).* После ввода блюда в «Питание» мастер предлагает чеклист типичных ингредиентов (локальный каталог) с возможным обогащением из Open Food Facts / product catalog. Отмеченные компоненты сверяются с аллергиями профиля (прямые и перекрёстные), конфликты подсвечиваются; поле аллергенов предзаполняется.
- **FR-DIARY-voice** *(Phase C — done).* На текстовых шагах wizard доступен голосовой ввод с **микрофона устройства** (без выбора файла): OS / on-device STT через `expo-speech-recognition` (Web Speech API в Chromium); при `EXPO_PUBLIC_YC_STT` + `EXPO_PUBLIC_YC_STT_MIC` и недоступном OS STT — запись mic (`expo-audio`) → `POST /api/stt`. Распознанный текст вставляется в текущее поле; для «Симптомы» лёгкий парсер может заполнить severity / onset / зону / код каталога, если поля пустые. Отказ в permission или ошибка STT не ломают wizard (text-fallback).

> **Планируется:** облачное хранение фото, расширение каталога блюд («свой компонент»), push-напоминания о визите к врачу.

## 9. Умный сканер аллергенов

### 9.1. Режимы сканирования

- **FR-SCAN-01.** Четыре режима: **Продукт**, **Меню**, **Лекарство**, **Косметика**.
- **FR-SCAN-02.** Режим «Продукт»: сканирование штрихкода камерой (EAN-13, EAN-8, UPC, Code128) **и/или** фото блюда/этикетки с обрезкой → OCR названия → поиск состава в Open Food Facts / локальном справочнике блюд → проверка аллергенов. Если на фото **только блюдо без текста**, опциональный multimodal vision (`EXPO_PUBLIC_AI_DISH_VISION`) оценивает название и вероятный состав за один вызов, затем сверяет с профилем; UI показывает усиленный disclaimer (оценка, не этикетка).
- **FR-SCAN-03.** Режимы «Меню», «Лекарство», «Косметика и быт»: съёмка камерой или выбор из галереи → **обрезка области в приложении** → OCR / ручной ввод состава (бытовая химия — в режиме косметики).
- **FR-SCAN-04.** Ручной ввод состава / штрихкода для всех режимов.

### 9.2. Анализ результата

- **FR-SCAN-05.** Проверка текста состава **и полного текста меню/этикетки** по ключевым словам аллергенов активного профиля (primary и отдельно перекрёстные).
- **FR-SCAN-06.** Учёт **перекрёстных реакций** из справочника аллергенов.
- **FR-SCAN-07.** Вердикт с уровнем риска: низкий / средний / высокий — в UI **три визуальных состояния** (СТОП / ОСТОРОЖНО / совпадений нет); для штрихкода — статусы `not_found` / `found_no_allergens` / `found_insufficient_composition` / `found_match` с карточкой продукта (название, бренд, категория при наличии, состав, изображение).
- **FR-SCAN-08.** Отображение совпадений (с alias keyword → аллерген при наличии), перекрёстных совпадений, источника данных (Open Food Facts, штрихкод, ручной ввод).
- **FR-SCAN-09.** История последних сканирований активного профиля (до 5 в UI, тап открывает результат); отдельно список сохранённых («безопасные»); dedupe повторов OCR-сессий (меню/лекарства/косметика).
- **FR-SCAN-10.** Disclaimer у результата (trust strip) и внизу экрана: результат предварительный, не исключает индивидуальной реакции.
- **FR-SCAN-11.** В режимах «Лекарство» и «Косметика» primary CTA — камера (с запросом permission); галерея — fallback.
- **FR-SCAN-12.** На экране сканера отображается chip активного профиля; без профиля — empty state. Перед сохранением в «безопасные» — подтверждение сверки упаковки.

> **Планируется:** полноценный OCR меню, распознавание состава с упаковки лекарств и косметики.

## 11. Карта мест

### 11.1. Единый экран карты

- **FR-MAP-01.** Один экран карты объединяет пыление, рестораны/аптеки и клиники АДАИР (фильтры POI вместо трёх изолированных вкладок). Слои UI: **Пыльца / Места / Оба**; status-first вердикт над картой (уровень · таксон · источник · обновлено).
  Legacy labels «Рестораны / Пыление / АДАИР» могут оставаться в i18n для совместимости.

### 11.2. Места (рестораны, аптеки, клиники)

- **FR-MAP-02.** Интерактивная карта с маркерами: Google Maps при наличии ключа/`EXPO_PUBLIC_GOOGLE_MAP_PRIMARY`; иначе виджет Яндекс.
- **FR-MAP-03.** Геолокация пользователя (с разрешением).
- **FR-MAP-04.** Список рекомендованных мест с уровнем: высокий / средний / низкий (badge в списке и легенда типов при слое «Места»).
- **FR-MAP-05.** Фильтрация curated-мест по аллергенам профиля; live Places — Nearby / Autocomplete / Text Search / Details через `EXPO_PUBLIC_MAP_PLACES` / API proxy. Google rating не является allergy safety (`allergySafety=unknown`). Hardcoded catalog — только маркированный региональный offline fallback.
- **FR-MAP-08.** Клиники АДАИР отображаются как medical POI (адрес, телефон, запись) и в списке.
- **FR-MAP-09.** Список врачей: ФИО, степень, специализация.
- **FR-MAP-10.** Отметка НККЦ и главного медицинского эксперта (badges в списке POI / специалистов).
- **FR-MAP-10a.** При moderate/high пыльцы — action tip + CTA «клиники рядом» (переключает слой на Места / medical).

### 11.3. Пыление

- **FR-MAP-06.** Отображение пиков пыления для текущего месяца (календарь АДАИР) при offline/пустом feed.
- **FR-MAP-07.** Карточка аллергена: описание, сезон/семейство (Google plantInfo при наличии), перекрёстные реакции из `@allerguide/core`.
- **FR-MAP-11.** Live-уровни берёзы, злаковых, амброзии (+ ольха, полынь, олива): Google `plantInfo` UPI (`BIRCH`/`ALDER`/`OLIVE`) если есть, иначе Open-Meteo grains/m³. Общий `TREE` не подставляется как уровень вида.
- **FR-MAP-12.** Чипы выбора таксона с цветовой точкой уровня; релевантные профилю отмечены.
- **FR-MAP-13.** Подложка: Google Maps primary при `EXPO_PUBLIC_GOOGLE_MAP_PRIMARY` или `EXPO_PUBLIC_POLLEN_HEATMAP=google`; Яндекс — fallback. Heatmap UPI через API proxy. Deep-link на 10-дневный прогноз Яндекс Погоды.
- **FR-MAP-14.** При недоступности live-данных — кэш или региональный календарь без блокировки экрана.
- **FR-MAP-15.** Универсальный индекс пыльцы (UPI 0–5): официальные категории Google (`Нет` … `Очень высокий`). Google Forecast proxy при наличии ключа, иначе оценка из Open-Meteo grains/m³. Не подписывать Google UPI как зёрна/м³.
- **FR-MAP-16.** Полоса multi-day прогноза (Open-Meteo hourly → daily peaks; до ~4 дней; Google Forecast до 5 при флаге).
- **FR-MAP-17.** Picker всегда показывает 17 Google map taxa (14 TREE, 1 GRASS, 2 WEED) по группам, независимо от сезона; вид без данных остаётся выбранным с no-data state.
- **FR-MAP-18.** Google pollen heatmap — только три групповых слоя (`TREE_UPI` / `GRASS_UPI` / `WEED_UPI`) с легендой и копирайтом, что подложка деревьев суммарная. Per-species heatmap нет (spike: [`pollen-species-heatmap-spike.md`](./pollen-species-heatmap-spike.md), решение no-go).
- **FR-MAP-19.** Карточка Google UAQI 0–100 (чем выше, тем чище), загрязнители и рекомендация; AQ overlay взаимоисключающ с pollen heatmap.
- **FR-MAP-20.** Карточка вида: имя, группа, in-season, family/season, признаки, перекрёстные реакции, UPI и health recommendation либо честный «нет текущих данных».

Архитектура и сравнение источников: [`yandex-pollen-map-integration.md`](./yandex-pollen-map-integration.md).

## 20. Критерии приёмки (общие)

1. Пользователь может пройти полный путь: регистрация → intro → сценарий → профиль → главная.
2. Для каждого типа записи дневника создаётся, редактируется и удаляется запись с корректным summary.
3. Сканер возвращает вердикт с учётом аллергенов профиля и перекрёстных реакций.
4. Wellness index на главной обновляется при смене профиля и наличии сети.
5. PDF-отчёт формируется за выбранный период с выбранными блоками.
6. SOS-экран показывает актуальные данные профиля (read-only) и инициирует звонок; правки — из профиля.
7. Резервная копия экспортируется и импортируется без потери данных.
8. Все медицинские экраны содержат обязательный disclaimer.
